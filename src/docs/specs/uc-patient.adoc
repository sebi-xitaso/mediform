== UC-P1: Fill Out a Questionnaire

[cols="1,3"]
|===
| ID | UC-P1
| Goal | Fill out a questionnaire and submit my responses
| Actor-Goal Ref | P-1
| Level | User Goal
| Primary Actor | Patient
|===

=== Stakeholders and Interests

Patient:: Wants to complete the questionnaire quickly and without confusion.
Nurse:: Wants to receive complete, valid responses.
Hospital:: Wants responses stored as standards-compliant FHIR resources for downstream analysis.

=== Trigger

The patient opens a questionnaire link received from the hospital.

=== Preconditions

. A questionnaire exists in Published status.
. The patient has a valid link or access code for the questionnaire.

=== Main Success Scenario

. The patient opens the questionnaire link in a browser.
. The system resolves the link and retrieves the published questionnaire.
. The system renders the questionnaire, displaying each question with its description and input control.
. For each question with a custom renderer, the system loads the renderer in a sandboxed iframe.
. The patient answers each question.
. The patient submits the completed questionnaire.
. The system validates that all required questions have answers.
. The system validates that each answer matches its declared value type.
. The system compiles the responses into a FHIR QuestionnaireResponse resource. _(SYS-4)_
. The system creates FHIR Observation resources for each mapped value. _(SYS-5)_
. The system stores the QuestionnaireResponse and Observations on the HAPI FHIR server. _(SYS-6)_
. The system displays a confirmation to the patient.

=== Extensions

*3a. The questionnaire contains sections.*::
  3a.1. The system renders section headings to group questions visually.
  3a.2. Continue with step 4.

*4a. A custom renderer fails to load.*::
  4a.1. The system displays a fallback message: "This question cannot be displayed."
  4a.2. The patient can still submit if the question is not required.
  4a.3. If the question is required, the patient cannot submit. The system displays an error.

*5a. A custom renderer calls `onValue` with an invalid type.*::
  5a.1. The system rejects the value silently and keeps the question unanswered.
  5a.2. The patient sees the question as incomplete.

*6a. The patient closes the browser before submitting.*::
  6a.1. Responses are lost. _(Prototype shortcut: no auto-save.)_

*7a. One or more required questions are unanswered.*::
  7a.1. The system highlights the unanswered required questions.
  7a.2. The patient returns to step 5.

*8a. An answer does not match its declared value type.*::
  8a.1. The system highlights the invalid answer with an error message.
  8a.2. The patient corrects the answer and returns to step 6.

*11a. The HAPI FHIR server is unreachable.*::
  11a.1. The system displays an error: "Your responses could not be saved. Please try again."
  11a.2. The patient retries from step 6.

=== Postconditions

Success Guarantee:: A FHIR QuestionnaireResponse and corresponding Observations exist on the HAPI server, linked to the questionnaire.
Minimal Guarantee:: No partial data is stored. Either all resources are created or none are.

=== Business Rules

[cols="1,4"]
|===
| ID | Rule

| BR-001 | All required questions must have an answer before submission.
| BR-002 | Each answer must match the value type declared in the `.mediform` format (`maps-to` field).
| BR-003 | Custom renderers run in a sandboxed iframe and cannot access data from other questions.
| BR-004 | Only questionnaires in Published status are accessible to patients.
| BR-005 | Response submission is atomic: all FHIR resources are created together or not at all.
|===

=== Activity Diagram

[plantuml]
----
@startuml
start
:Patient opens questionnaire link;

:System resolves link and retrieves questionnaire;
if (Questionnaire found and Published?) then (yes)
else (no)
  :Display error: questionnaire not available;
  stop
endif

:Render questionnaire with questions;

while (More questions to render?) is (yes)
  if (Question has custom renderer?) then (yes)
    :Load renderer in sandboxed iframe;
    if (Renderer loads?) then (yes)
      :Display custom renderer;
    else (no)
      :Display fallback message;
      note right: Question marked\nas unavailable
    endif
  else (no)
    :Render built-in input control;
  endif
endwhile (no)

:Patient answers questions;

:Patient submits;

:Validate required questions;
if (All required questions answered?) then (yes)
else (no)
  :Highlight unanswered required questions;
  backward:Patient answers questions;
endif

:Validate answer types;
if (All answers match declared types?) then (yes)
else (no)
  :Highlight invalid answers;
  backward:Patient answers questions;
endif

:Compile responses to FHIR QuestionnaireResponse;
:Create FHIR Observations for mapped values;

:Store on HAPI FHIR server;
if (Storage succeeded?) then (yes)
  :Display confirmation;
else (no)
  :Display error: could not save;
  backward:Patient submits;
endif

stop
@enduml
----

=== Acceptance Criteria

[source,gherkin]
----
Feature: Fill out a questionnaire

  Background:
    Given a questionnaire "Post-Op Pain Assessment" in Published status
    And the patient has a valid link to the questionnaire

  Scenario: Successfully fill out and submit a questionnaire
    When the patient opens the questionnaire link
    Then the system displays the questionnaire with all questions rendered
    When the patient answers all required questions with valid values
    And the patient submits the questionnaire
    Then the system stores a FHIR QuestionnaireResponse on the HAPI server
    And the system stores FHIR Observations for each mapped value
    And the patient sees a confirmation message

  Scenario: Submit with unanswered required questions
    When the patient opens the questionnaire link
    And the patient leaves a required question unanswered
    And the patient submits the questionnaire
    Then the system highlights the unanswered required questions
    And no data is stored on the HAPI server

  Scenario: Submit with an invalid answer type
    When the patient opens the questionnaire link
    And the patient provides a text value for an integer question
    And the patient submits the questionnaire
    Then the system highlights the invalid answer with an error message
    And no data is stored on the HAPI server

  Scenario: Custom renderer fails to load
    Given the questionnaire contains a question with a custom renderer
    And the renderer code has a runtime error
    When the patient opens the questionnaire link
    Then the system displays a fallback message for that question
    And all other questions render normally

  Scenario: Custom renderer produces an invalid value type
    Given the questionnaire contains a custom renderer that maps to decimal
    When the renderer calls onValue with a string
    Then the system rejects the value
    And the question appears as unanswered

  Scenario: FHIR server is unreachable on submit
    When the patient fills out all questions and submits
    And the HAPI FHIR server is unreachable
    Then the system displays an error asking the patient to retry
    And no partial data is stored

  Scenario: Questionnaire link points to a non-published questionnaire
    Given a questionnaire in Draft status
    When the patient opens a link to that questionnaire
    Then the system displays an error: questionnaire not available
----

== UC-P2: View a Previously Completed Questionnaire

[cols="1,3"]
|===
| ID | UC-P2
| Goal | View a previously completed questionnaire
| Actor-Goal Ref | P-2
| Level | User Goal
| Primary Actor | Patient
|===

=== Stakeholders and Interests

Patient:: Wants to review what they submitted.
Hospital:: Wants patients to have read-only access to their own responses.

=== Trigger

The patient opens a link to a completed questionnaire response.

=== Preconditions

. A QuestionnaireResponse exists on the HAPI FHIR server for this patient and questionnaire.
. The patient has a valid link to the response.

=== Main Success Scenario

. The patient opens the response link in a browser.
. The system resolves the link and retrieves the QuestionnaireResponse from HAPI FHIR.
. The system retrieves the associated questionnaire definition.
. The system renders the questionnaire in read-only mode, displaying each question with the patient's recorded answer.
. The patient reviews their responses.

=== Extensions

*2a. The response does not exist or the link is invalid.*::
  2a.1. The system displays an error: "Response not found."

*4a. A custom renderer is present in the questionnaire.*::
  4a.1. The system renders the custom question in read-only mode, displaying the stored value as text.
  4a.2. _(Prototype shortcut: custom renderers do not support a read-only replay mode. The stored value is shown as plain text.)_

=== Postconditions

Success Guarantee:: The patient sees their recorded responses. No data is modified.
Minimal Guarantee:: No data is modified.

=== Business Rules

[cols="1,4"]
|===
| ID | Rule

| BR-006 | Completed responses are read-only. The patient cannot edit a submitted response.
| BR-007 | The system displays the stored answer values, not re-executed renderer output.
|===

=== Activity Diagram

[plantuml]
----
@startuml
start
:Patient opens response link;

:System resolves link;
if (Response found?) then (yes)
else (no)
  :Display error: response not found;
  stop
endif

:Retrieve QuestionnaireResponse from HAPI FHIR;
:Retrieve associated questionnaire definition;

:Render questionnaire in read-only mode\nwith recorded answers;

:Patient reviews responses;

stop
@enduml
----

=== Acceptance Criteria

[source,gherkin]
----
Feature: View a previously completed questionnaire

  Background:
    Given a questionnaire "Post-Op Pain Assessment" in Published status
    And the patient has previously submitted responses to it
    And the patient has a valid link to the response

  Scenario: View completed responses
    When the patient opens the response link
    Then the system displays the questionnaire in read-only mode
    And each question shows the patient's recorded answer
    And no input controls are editable

  Scenario: View response with a custom renderer question
    Given the questionnaire contains a custom renderer question
    When the patient opens the response link
    Then the custom renderer question displays the stored value as plain text

  Scenario: Invalid response link
    When the patient opens an invalid response link
    Then the system displays an error: response not found
----
