== Overview

This document derives system-level use cases from the persona use cases
(uc-patient.adoc, uc-nurse.adoc, uc-trained-staff.adoc) and the business
rules index (business-rules.adoc).

Each system use case describes a concrete interface: an API endpoint, an
internal processing step, or a file format contract.
Requirements within each use case use EARS syntax
(When/While/If/Shall) where applicable.

=== Conventions

Base URL:: All API paths are relative to the Elysia server root.
Content type:: All request and response bodies are `application/json` unless stated otherwise.
API client:: Both Svelte SPAs use Eden Treaty to consume the Elysia API with end-to-end type safety. The TypeScript interfaces in this document describe the wire format; Eden Treaty derives equivalent types from the Elysia route definitions at build time.
IDs:: Questionnaire IDs are opaque strings (UUIDs). Response IDs are opaque strings.
Auth:: _(Prototype shortcut: no authentication. All endpoints are open. See PRD, Out of Scope.)_

== Patient API

=== SUC-01: Get Published Questionnaire for Fill-In

[cols="1,3"]
|===
| ID | SUC-01
| Persona UC | UC-P1 (steps 1-4)
| Interface | REST API endpoint
|===

==== Trigger and Preconditions

[cols="1,3"]
|===
| HTTP method | GET
| Path | /patient/questionnaires/:id
| Precondition | Questionnaire with `:id` exists and is in Published status (BR-004).
|===

==== Input

[cols="1,3"]
|===
| Parameter | Description

| `:id` (path) | Questionnaire UUID. Required. Format: UUID v4.
|===

No request body.

==== Processing

. Retrieve the questionnaire record by ID.
. *If* the questionnaire does not exist, *the system shall* return 404.
. *If* the questionnaire status is not `published`, *the system shall* return 404. _(BR-004: patients see only published questionnaires.)_
. *If* the questionnaire status is `retired`, *the system shall* return 410 Gone. _(BR-032)_
. Parse the stored `.mediform` source. _(SUC-10)_
. Compile to a renderable structure: sections, questions with descriptions, input types, options, and custom renderer code. _(SUC-10)_
. Strip FHIR-internal metadata (LOINC codes, SNOMED codes, `maps-to`) from the response. Patients do not need it.

==== Output

[cols="1,1,3"]
|===
| Status | Code | Description

| Success | 200 | Renderable questionnaire structure.
| Not found | 404 | Questionnaire does not exist or is not published.
| Gone | 410 | Questionnaire is retired.
|===

.200 response schema
[source,typescript]
----
interface PatientQuestionnaire {
  id: string;
  title: string;
  description: string;
  sections: Section[];
}

interface Section {
  title: string | null;       // null for the implicit root section
  questions: PatientQuestion[];
}

interface PatientQuestion {
  id: string;                 // question identifier within the questionnaire
  title: string;
  description: string;        // markdown
  type: "boolean" | "integer" | "decimal" | "string" | "date"
      | "choice" | "scale" | "custom";
  required: boolean;
  config: Record<string, unknown>;  // type-specific: options, min, max, step, unit
  renderer?: string;          // JS source code, present only when type = "custom"
}
----

==== Error Responses

[cols="1,2,2"]
|===
| Code | Message | Recovery

| 404 | `Questionnaire not found` | Check the link. The questionnaire may not exist or may not be published yet.
| 410 | `Questionnaire retired` | This questionnaire is no longer accepting responses.
| 500 | `Internal server error` | Retry. If persistent, contact support.
|===

==== Non-Functional Requirements

NFR-01:: *When* a patient requests a published questionnaire, *the system shall* respond within 500ms under normal load.
NFR-02:: _(Prototype shortcut: no rate limiting.)_

'''

=== SUC-02: Submit Questionnaire Response

[cols="1,3"]
|===
| ID | SUC-02
| Persona UC | UC-P1 (steps 6-12)
| Interface | REST API endpoint
|===

==== Trigger and Preconditions

[cols="1,3"]
|===
| HTTP method | POST
| Path | /patient/questionnaires/:id/responses
| Precondition | Questionnaire with `:id` exists and is in Published status (BR-004).
|===

==== Input

[cols="1,3"]
|===
| Parameter | Description

| `:id` (path) | Questionnaire UUID. Required.
|===

.Request body schema
[source,typescript]
----
interface SubmitResponseRequest {
  answers: Answer[];
}

interface Answer {
  questionId: string;
  value: unknown;  // must match the question's maps-to type
}
----

==== Validation Rules

. *The system shall* reject the request *if* any required question (per the `.mediform` definition) has no corresponding answer. _(BR-001)_
. *The system shall* reject the request *if* any answer value does not match the declared `maps-to` type for that question. _(BR-002)_
. *The system shall* reject the request *if* the questionnaire is not in Published status. _(BR-004)_
. *The system shall* reject the request *if* the questionnaire is in Retired status. _(BR-032)_
. *The system shall* ignore answers for question IDs that do not exist in the questionnaire.

==== Processing

. Retrieve the questionnaire and its `.mediform` definition.
. Validate the request against the rules above.
. *If* validation fails, *the system shall* return 422 with details.
. Compile answers into a FHIR QuestionnaireResponse resource. _(SUC-11)_
. For each answer mapped to an Observation (via `loinc` field), create a FHIR Observation resource. _(SUC-11)_
. Store the QuestionnaireResponse and all Observations on the HAPI FHIR server atomically. _(BR-005)_
. *If* HAPI FHIR storage fails, *the system shall* return 502 and store nothing. _(BR-005)_
. Generate a response link for the patient.

==== Output

[cols="1,1,3"]
|===
| Status | Code | Description

| Created | 201 | Response stored. Returns response ID and link.
| Bad request | 400 | Malformed JSON.
| Not found | 404 | Questionnaire not found or not published.
| Gone | 410 | Questionnaire retired.
| Unprocessable | 422 | Validation failed (missing answers, type mismatch).
| Bad gateway | 502 | HAPI FHIR server unreachable or returned an error.
|===

.201 response schema
[source,typescript]
----
interface SubmitResponseResult {
  responseId: string;
  responseLink: string;   // URL for UC-P2
  fhirQuestionnaireResponseId: string;
  observationIds: string[];
}
----

.422 response schema
[source,typescript]
----
interface ValidationError {
  errors: {
    questionId: string;
    code: "REQUIRED" | "TYPE_MISMATCH" | "UNKNOWN_QUESTION";
    message: string;
    expected?: string;  // expected type, for TYPE_MISMATCH
    received?: string;  // actual type, for TYPE_MISMATCH
  }[];
}
----

==== Error Responses

[cols="1,2,2"]
|===
| Code | Message | Recovery

| 400 | `Malformed request body` | Fix JSON syntax.
| 404 | `Questionnaire not found` | Check the questionnaire ID.
| 410 | `Questionnaire retired` | This questionnaire no longer accepts responses.
| 422 | `Validation failed` | See `errors` array for details. Fix and resubmit.
| 502 | `FHIR server unavailable` | Retry later. No data was stored.
|===

==== Non-Functional Requirements

NFR-03:: *When* a patient submits a response, *the system shall* complete validation within 200ms.
NFR-04:: *When* a patient submits a response, *the system shall* complete FHIR storage within 2000ms.
NFR-05:: *The system shall* guarantee atomicity: either all FHIR resources (QuestionnaireResponse + Observations) are created, or none are. _(BR-005)_

=== SUC-04: Import Questionnaire

[cols="1,3"]
|===
| ID | SUC-04
| Persona UC | UC-N1
| Interface | REST API endpoint
|===

==== Trigger and Preconditions

[cols="1,3"]
|===
| HTTP method | POST
| Path | /staff/questionnaires/import
| Precondition | None.
|===

==== Input

.Request body schema
[source,typescript]
----
interface ImportRequest {
  source: string;   // raw .mediform file content
}
----

==== Validation Rules

. *The system shall* parse the `source` field as a `.mediform` file. _(SUC-10)_
. *If* the source has syntax errors, *the system shall* return 422 with error details including line numbers. _(BR-008)_
. *If* required metadata fields are missing, *the system shall* include warnings in the response but not reject the request. _(BR-010)_

==== Processing

. Parse and validate the `.mediform` source. _(SUC-10)_
. *If* syntax is invalid, return 422.
. Check for missing required metadata fields (title, maps-to on each question, loinc on each question).
. Create a new questionnaire record in Draft status. _(BR-009)_
. Store the raw `.mediform` source and the parsed structure.
. Return the created questionnaire with any warnings.

==== Output

[cols="1,1,3"]
|===
| Status | Code | Description

| Created | 201 | Questionnaire created in Draft status.
| Bad request | 400 | Missing `source` field or empty content.
| Unprocessable | 422 | Syntax errors in `.mediform` source.
|===

.201 response schema
[source,typescript]
----
interface ImportResult {
  questionnaire: QuestionnaireRecord;
  warnings: MetadataWarning[];
}

interface MetadataWarning {
  questionId?: string;    // null for questionnaire-level warnings
  field: string;          // e.g., "loinc", "maps-to", "title"
  message: string;
}
----

.422 response schema
[source,typescript]
----
interface ParseError {
  errors: {
    line: number;
    column?: number;
    message: string;
  }[];
}
----

==== Error Responses

[cols="1,2,2"]
|===
| Code | Message | Recovery

| 400 | `Missing or empty source` | Provide the `.mediform` file content in the `source` field.
| 422 | `Syntax errors in .mediform source` | See `errors` array. Fix the source and retry.
| 500 | `Internal server error` | Retry.
|===

==== Non-Functional Requirements

NFR-07:: *When* a nurse imports a `.mediform` file, *the system shall* parse and validate within 300ms for files up to 50KB.

[cols="1,3"]

[cols="1,3"]
|===
| HTTP method | POST
| Path | /staff/questionnaires/:id/submit

|===

==== Input

[cols="1,3"]
|===
| Parameter | Description

| `:id` (path) | Questionnaire UUID. Required.
|===

No request body.

==== Validation Rules

. *The system shall* reject the request *if* the questionnaire is not in Draft status.

. *If* not found, return 404.
. *If* status is not Draft, return 409.

. *If* required metadata is missing, return 422.
. Run automated quality checks. _(SUC-14-internal)_

.. All required metadata fields present (already confirmed).
.. FHIR codes reference known code systems (LOINC, SNOMED).
.. Custom renderers parse without JS syntax errors.

. Store the quality check results.

| Not found | 404 | Questionnaire not found.

== Internal Processing

=== SUC-10: Parse and Compile `.mediform` Source

[cols="1,3"]
|===
| ID | SUC-10
| Actor-Goal Ref | SYS-1, SYS-2
| Interface | Internal module (not an HTTP endpoint)
|===

This is the core compilation pipeline, invoked by SUC-01, SUC-04, SUC-05, SUC-06, SUC-07, and SUC-12.

==== Input

[source,typescript]
----
interface ParseInput {
  source: string;   // raw .mediform content
}
----

==== Processing: Parse Phase (SYS-1)

. Extract YAML frontmatter (delimited by `---`).
. *If* frontmatter is missing or malformed YAML, *the system shall* produce a parse error with line number.
. Parse the body:
.. `##` headings become sections.
.. `#` headings become questions.
.. Prose lines (non-metadata) below a heading become the question description (markdown).
.. Lines starting with `- key: value` become metadata properties.
.. Lines starting with `- key:` followed by indented sub-items become structured metadata (e.g., options).
.. Fenced code blocks tagged `js` within a `renderer:` property become custom renderer source.
. *If* any structural rule is violated, *the system shall* produce a parse error with line number and column.
. Validate required fields per question: `type` is always required.
. Validate metadata field values: `type` must be one of the known types, `maps-to` must be a known FHIR answer type, `required` must be boolean.

==== Processing: Compile Phase (SYS-2)

. Map the parsed structure to a FHIR Questionnaire resource:
.. Frontmatter `title` -> `Questionnaire.title`
.. Frontmatter `description` -> `Questionnaire.description`
.. Frontmatter `status` -> `Questionnaire.status` (mapped to FHIR status codes)
.. Each section -> `Questionnaire.item` with `type: "group"`
.. Each question -> `Questionnaire.item` with appropriate `type` and `code` (from `loinc`)
.. `options` with SNOMED codes -> `answerOption` with `valueCoding`
.. `maps-to` -> determines the FHIR answer type
. *If* a LOINC or SNOMED code is syntactically malformed, *the system shall* produce a compilation error.

==== Output

=== SUC-11: Compile Responses to FHIR

[cols="1,3"]
|===
| ID | SUC-11
| Actor-Goal Ref | SYS-4, SYS-5
| Interface | Internal module (not an HTTP endpoint)
|===

Invoked by SUC-02 during response submission.

==== Input

[source,typescript]
----
interface CompileResponseInput {
  questionnaire: ParsedQuestionnaire;
  answers: Answer[];
}
----

==== Processing

. For each answer:
.. Look up the corresponding question in the parsed questionnaire.
.. Map the answer value to the FHIR type declared in `maps-to`.
.. Create a `QuestionnaireResponse.item` entry.
. Assemble the full FHIR QuestionnaireResponse resource:
.. `questionnaire` reference -> the FHIR Questionnaire ID on HAPI.
.. `status` -> `completed`.
.. `authored` -> current timestamp.
. For each answer where the question has a `loinc` code:
.. Create a FHIR Observation resource:
... `code` -> LOINC code from the question.
... `value[x]` -> the answer value, typed according to `maps-to`.
... `status` -> `final`.
... `derivedFrom` -> reference to the QuestionnaireResponse.
. *If* a value cannot be mapped to the declared FHIR type, *the system shall* produce a compilation error. _(This should not happen if SUC-02 validation passed, but is a safety net.)_

==== Output

[source,typescript]
----
interface CompileResponseResult {
  questionnaireResponse: FHIRQuestionnaireResponse;
  observations: FHIRObservation[];
  errors: { questionId: string; message: string }[];
}
----

==== Non-Functional Requirements

NFR-16:: *The system shall* compile a response with up to 50 answers within 100ms.

|===

==== Processing

. Retrieve the questionnaire by ID.
. *If* not found, return 404.
. *If* status is not Approved, return 409. _(BR-026)_
. Compile the `.mediform` source to a FHIR Questionnaire resource. _(SUC-10)_
. *If* compilation fails, return 422. _(BR-029)_
. Store the FHIR Questionnaire on the HAPI FHIR server with status `active`. _(BR-027)_
. *If* HAPI storage fails, return 502. _(BR-029)_
. Transition the questionnaire to Published status.
. Generate a patient-facing link. _(BR-028)_

| Not found | 404 | Questionnaire not found.
