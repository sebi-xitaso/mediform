== UC-N1: Import a Questionnaire

[cols="1,3"]
|===
| ID | UC-N1
| Goal | Import a new questionnaire from an AI-generated `.mediform` file
| Actor-Goal Ref | N-1
| Level | User Goal
| Primary Actor | Nurse
|===

=== Stakeholders and Interests

Nurse:: Wants to turn an AI-generated file into a usable questionnaire without technical effort.
Trained Staff:: Wants imported questionnaires to be syntactically valid before they reach review.
Hospital:: Wants FHIR metadata present from the start so compilation succeeds later.

=== Trigger

The nurse has a `.mediform` file (generated by an external LLM) and wants to add it to the system.

=== Preconditions

. The nurse has access to the employee app.
. The nurse has a `.mediform` file ready to paste or upload.

=== Main Success Scenario

. The nurse opens the import screen in the employee app.
. The nurse pastes or uploads the `.mediform` file content.
. The system parses the file and validates its syntax. _(SYS-1)_
. The system displays the parsed questionnaire: title, description, sections, questions, and metadata.
. The nurse reviews the parsed result.
. The nurse confirms the import.
. The system stores the questionnaire in Draft status. _(SYS-6)_
. The system displays the questionnaire in the nurse's list.

=== Extensions

*3a. The file has syntax errors.*::
  3a.1. The system displays the errors with line numbers and descriptions.
  3a.2. The nurse corrects the file content and returns to step 2.

*3b. Required metadata fields are missing (e.g., title, maps-to on a question).*::
  3b.1. The system displays warnings for each missing field.
  3b.2. The nurse may still import (the file is syntactically valid) but the questionnaire cannot be submitted for review until the fields are filled.

*5a. The nurse notices a problem in the parsed result.*::
  5a.1. The nurse cancels the import.
  5a.2. The nurse edits the file externally and returns to step 2.

*7a. Storage fails.*::
  7a.1. The system displays an error.
  7a.2. The nurse retries from step 6.

=== Postconditions

Success Guarantee:: A new questionnaire exists in Draft status, parsed from the `.mediform` file, stored in the system.
Minimal Guarantee:: No questionnaire is created. The original file is unchanged.

=== Business Rules

[cols="1,4"]
|===
| ID | Rule

| BR-008 | A `.mediform` file must pass syntax validation before import.
| BR-009 | Imported questionnaires always start in Draft status.
| BR-010 | Missing metadata fields produce warnings, not blocking errors, at import time.
|===

=== Activity Diagram

[plantuml]
----
@startuml
start
:Nurse opens import screen;
:Nurse pastes or uploads .mediform content;

:System parses and validates syntax;
if (Syntax valid?) then (yes)
else (no)
  :Display errors with line numbers;
  backward:Nurse pastes or uploads .mediform content;
endif

:Check required metadata fields;
if (All present?) then (yes)
else (no)
  :Display warnings for missing fields;
  note right: Import allowed,\nreview blocked
endif

:Display parsed questionnaire;

:Nurse reviews;
if (Nurse confirms import?) then (yes)
else (no)
  :Cancel import;
  stop
endif

:Store questionnaire in Draft status;
if (Storage succeeded?) then (yes)
  :Display questionnaire in nurse's list;
else (no)
  :Display error;
  backward:Nurse reviews;
endif

stop
@enduml
----

=== Acceptance Criteria

[source,gherkin]
----
Feature: Import a questionnaire

  Scenario: Import a valid .mediform file
    Given the nurse is on the import screen
    When the nurse pastes a valid .mediform file
    Then the system displays the parsed questionnaire with title, questions, and metadata
    When the nurse confirms the import
    Then a new questionnaire exists in Draft status
    And it appears in the nurse's questionnaire list

  Scenario: Import a file with syntax errors
    Given the nurse is on the import screen
    When the nurse pastes a .mediform file with syntax errors
    Then the system displays errors with line numbers
    And no questionnaire is created

  Scenario: Import a file with missing metadata
    Given the nurse is on the import screen
    When the nurse pastes a syntactically valid file missing a LOINC code on one question
    Then the system displays a warning about the missing field
    And the nurse can still confirm the import
    And the questionnaire is created in Draft status

  Scenario: Cancel import after review
    Given the nurse is on the import screen
    When the nurse pastes a valid .mediform file
    And the nurse cancels the import
    Then no questionnaire is created
----

== UC-N2: Preview a Questionnaire

[cols="1,3"]
|===
| ID | UC-N2
| Goal | Preview a questionnaire as a patient would see it
| Actor-Goal Ref | N-2
| Level | User Goal
| Primary Actor | Nurse
|===

=== Stakeholders and Interests

Nurse:: Wants to verify the questionnaire looks correct before submitting it for review.
Patient (indirect):: Benefits from a nurse catching layout or wording issues early.

=== Trigger

The nurse wants to see how a questionnaire will appear to a patient.

=== Preconditions

. A questionnaire exists in Draft or later status.
. The nurse has access to the questionnaire.

=== Main Success Scenario

. The nurse opens a questionnaire from their list.
. The nurse selects "Preview."
. The system compiles the `.mediform` definition into a rendered form. _(SYS-1, SYS-2)_
. The system displays the questionnaire as a patient would see it, including sections, descriptions, and input controls.
. For questions with custom renderers, the system loads the renderer in a sandboxed iframe.
. The nurse interacts with the preview (fills in test answers) to verify behavior.
. The nurse closes the preview.

=== Extensions

*3a. The `.mediform` definition has errors that prevent rendering.*::
  3a.1. The system displays the errors.
  3a.2. The nurse closes the preview and edits the questionnaire (UC-N3).

*5a. A custom renderer fails to load.*::
  5a.1. The system displays a fallback message for that question.
  5a.2. The nurse sees which renderer failed and can edit the code (UC-N3).

=== Postconditions

Success Guarantee:: The nurse has seen the patient-facing rendering. No data is stored or modified.
Minimal Guarantee:: No data is stored or modified.

=== Business Rules

[cols="1,4"]
|===
| ID | Rule

| BR-011 | Preview does not store any data. Test answers are discarded.
| BR-012 | Preview renders the questionnaire identically to the patient app.
|===

=== Activity Diagram

[plantuml]
----
@startuml
start
:Nurse opens questionnaire;
:Nurse selects Preview;

:System compiles .mediform to rendered form;
if (Compilation succeeds?) then (yes)
else (no)
  :Display compilation errors;
  stop
endif

:Display questionnaire as patient would see it;

while (More questions?) is (yes)
  if (Custom renderer?) then (yes)
    :Load renderer in iframe;
    if (Loads?) then (yes)
      :Display renderer;
    else (no)
      :Display fallback;
    endif
  else (no)
    :Display built-in control;
  endif
endwhile (no)

:Nurse interacts with preview;
:Nurse closes preview;

stop
@enduml
----

=== Acceptance Criteria

[source,gherkin]
----
Feature: Preview a questionnaire

  Scenario: Preview a valid questionnaire
    Given a questionnaire "Post-Op Pain Assessment" in Draft status
    When the nurse selects Preview
    Then the system displays the questionnaire as a patient would see it
    And all questions are rendered with their descriptions and input controls
    And sections are displayed with headings

  Scenario: Preview with a working custom renderer
    Given the questionnaire contains a custom renderer question
    When the nurse selects Preview
    Then the custom renderer loads in a sandboxed iframe
    And the nurse can interact with it

  Scenario: Preview with a broken custom renderer
    Given the questionnaire contains a custom renderer with a syntax error
    When the nurse selects Preview
    Then the broken question displays a fallback message
    And all other questions render normally

  Scenario: Preview does not persist data
    When the nurse fills in test answers during preview
    And the nurse closes the preview
    Then no data is stored on the FHIR server
----

== UC-N3: Edit a Questionnaire

[cols="1,3"]
|===
| ID | UC-N3
| Goal | Edit a questionnaire (fix text, reorder questions, adjust options)
| Actor-Goal Ref | N-3, N-6
| Level | User Goal
| Primary Actor | Nurse
|===

NOTE: This use case also covers N-6 (revise after changes requested).
The only difference is the trigger and precondition: N-6 is triggered by a review requesting changes, which moves the questionnaire back to Draft.

=== Stakeholders and Interests

Nurse:: Wants to correct or improve a questionnaire without re-importing.
Trained Staff:: Wants requested changes to be addressed before re-submission.

=== Trigger

* The nurse wants to improve a questionnaire in Draft status, _or_
* A trained staff member has requested changes, returning the questionnaire to Draft.

=== Preconditions

. The questionnaire is in Draft status.
. The nurse has access to the questionnaire.

=== Main Success Scenario

. The nurse opens the questionnaire from their list.
. The system displays the `.mediform` source in an editor.
. The nurse edits the source (fixes text, reorders questions, adjusts options, modifies metadata, edits custom renderer code).
. The system validates the edited source on each change. _(SYS-1)_
. The system displays validation results (errors, warnings) inline.
. The nurse saves the changes.
. The system stores the updated questionnaire. _(SYS-6)_

=== Extensions

*2a. The questionnaire was returned from review with feedback.*::
  2a.1. The system displays the reviewer's feedback alongside the editor.
  2a.2. Continue with step 3.

*4a. The edited source has syntax errors.*::
  4a.1. The system highlights errors inline in the editor.
  4a.2. The nurse can still save (Draft status allows invalid content) but cannot submit for review.

*6a. The nurse wants to preview before saving.*::
  6a.1. The nurse selects Preview (UC-N2) from the editor.
  6a.2. After closing the preview, the nurse returns to step 3.

=== Postconditions

Success Guarantee:: The questionnaire is updated with the nurse's changes, still in Draft status.
Minimal Guarantee:: The previous version of the questionnaire is preserved if the nurse does not save.

=== Business Rules

[cols="1,4"]
|===
| ID | Rule

| BR-013 | Only questionnaires in Draft status can be edited.
| BR-014 | Saving a draft with syntax errors is allowed. Submitting for review is not.
| BR-015 | When a questionnaire is returned from review, the reviewer's feedback is visible in the editor.
|===

=== Activity Diagram

[plantuml]
----
@startuml
start
:Nurse opens questionnaire;

if (Returned from review?) then (yes)
  :Display reviewer feedback;
else (no)
endif

:Display .mediform source in editor;

repeat
  :Nurse edits source;
  :System validates on change;
  if (Errors?) then (yes)
    :Highlight errors inline;
  else (no)
  endif

  if (Nurse wants preview?) then (yes)
    :Open preview (UC-N2);
    :Close preview;
  else (no)
  endif
repeat while (Nurse continues editing?) is (yes)

:Nurse saves;
:Store updated questionnaire;

stop
@enduml
----

=== Acceptance Criteria

[source,gherkin]
----
Feature: Edit a questionnaire

  Scenario: Edit question text
    Given a questionnaire in Draft status
    When the nurse opens the questionnaire editor
    And changes the text of a question
    And saves
    Then the questionnaire is updated with the new text

  Scenario: Edit with inline validation
    Given a questionnaire in Draft status
    When the nurse introduces a syntax error in the editor
    Then the system highlights the error inline
    And the nurse can still save the draft

  Scenario: Edit a questionnaire returned from review
    Given a questionnaire returned to Draft with feedback "Fix LOINC code on question 3"
    When the nurse opens the questionnaire editor
    Then the reviewer's feedback is displayed alongside the editor
    And the nurse can edit and save

  Scenario: Cannot edit a non-draft questionnaire
    Given a questionnaire in Published status
    When the nurse tries to open the editor
    Then the system does not allow editing

  Scenario: Preview during editing
    Given a questionnaire in Draft status
    When the nurse is editing and selects Preview
    Then the system displays the current (unsaved) version as a patient would see it
----

== UC-N4: Submit a Questionnaire for Review

[cols="1,3"]
|===
| ID | UC-N4
| Goal | Submit a questionnaire for review
| Actor-Goal Ref | N-4
| Level | User Goal
| Primary Actor | Nurse
|===

=== Stakeholders and Interests

Nurse:: Wants the questionnaire to move forward in the lifecycle.
Trained Staff:: Wants to receive only questionnaires that pass basic automated checks.

=== Trigger

The nurse considers a questionnaire ready for review.

=== Preconditions

. The questionnaire is in Draft status.
. The questionnaire has no syntax errors.
. All required metadata fields are present.

=== Main Success Scenario

. The nurse opens the questionnaire.
. The nurse selects "Submit for Review."
. The system runs automated quality checks. _(SYS-3)_
. All checks pass.
. The system transitions the questionnaire to Review status.
. The system notifies trained staff that a questionnaire is ready for review. _(Prototype shortcut: notification may be a dashboard update only, no push notification.)_

=== Extensions

*3a. Automated quality checks fail.*::
  3a.1. The system displays the failed checks with details.
  3a.2. The questionnaire remains in Draft status.
  3a.3. The nurse edits the questionnaire (UC-N3) and retries.

*2a. The questionnaire has syntax errors or missing required metadata.*::
  2a.1. The system blocks submission and displays the issues.
  2a.2. The nurse edits the questionnaire (UC-N3).

=== Postconditions

Success Guarantee:: The questionnaire is in Review status. Automated quality checks passed.
Minimal Guarantee:: The questionnaire remains in Draft status. No status change occurs.

=== Business Rules

[cols="1,4"]
|===
| ID | Rule

| BR-016 | A questionnaire cannot be submitted for review if it has syntax errors.
| BR-017 | A questionnaire cannot be submitted for review if required metadata fields are missing.
| BR-018 | Automated quality checks run on every submission to review.
| BR-019 | All automated checks must pass for the status to transition to Review.
|===

=== Activity Diagram

[plantuml]
----
@startuml
start
:Nurse opens questionnaire;
:Nurse selects Submit for Review;

if (Syntax valid and metadata complete?) then (yes)
else (no)
  :Display blocking issues;
  stop
endif

:Run automated quality checks;
if (All checks pass?) then (yes)
  :Transition to Review status;
  :Update dashboard for trained staff;
else (no)
  :Display failed checks with details;
  :Questionnaire remains in Draft;
endif

stop
@enduml
----

=== Acceptance Criteria

[source,gherkin]
----
Feature: Submit a questionnaire for review

  Scenario: Submit a valid questionnaire
    Given a questionnaire in Draft status with no errors and all metadata present
    When the nurse selects Submit for Review
    Then the system runs automated quality checks
    And all checks pass
    And the questionnaire transitions to Review status

  Scenario: Submit blocked by syntax errors
    Given a questionnaire in Draft status with syntax errors
    When the nurse selects Submit for Review
    Then the system blocks submission
    And displays the syntax errors
    And the questionnaire remains in Draft status

  Scenario: Submit blocked by missing metadata
    Given a questionnaire in Draft status missing a LOINC code
    When the nurse selects Submit for Review
    Then the system blocks submission
    And displays the missing metadata warning
    And the questionnaire remains in Draft status

  Scenario: Automated quality check fails
    Given a questionnaire in Draft status that references an unknown code system
    When the nurse selects Submit for Review
    Then the system displays the failed quality check
    And the questionnaire remains in Draft status
----

== UC-N5: View My Questionnaires

[cols="1,3"]
|===
| ID | UC-N5
| Goal | View the list of my questionnaires and their statuses
| Actor-Goal Ref | N-5
| Level | User Goal
| Primary Actor | Nurse
|===

=== Stakeholders and Interests

Nurse:: Wants an overview of all questionnaires they have created and their current lifecycle status.

=== Trigger

The nurse opens the employee app.

=== Preconditions

. The nurse has access to the employee app.

=== Main Success Scenario

. The nurse opens the questionnaire list screen.
. The system retrieves all questionnaires created by the nurse.
. The system displays the list with title, status, and last-modified date for each questionnaire.
. The nurse scans the list.

=== Extensions

*2a. The nurse has no questionnaires.*::
  2a.1. The system displays an empty state with a prompt to import a questionnaire.

*4a. The nurse wants to filter by status.*::
  4a.1. The nurse selects a status filter.
  4a.2. The system displays only questionnaires matching the selected status.

=== Postconditions

Success Guarantee:: The nurse sees an accurate list of their questionnaires with current statuses.
Minimal Guarantee:: No data is modified.

=== Business Rules

[cols="1,4"]
|===
| ID | Rule

| BR-020 | The list shows only questionnaires created by the current nurse. _(Prototype shortcut: without auth, this may show all questionnaires.)_
|===

=== Activity Diagram

[plantuml]
----
@startuml
start
:Nurse opens questionnaire list;

:System retrieves questionnaires;
if (Any questionnaires?) then (yes)
  :Display list with title, status, last-modified;
  if (Nurse applies status filter?) then (yes)
    :Filter list by status;
  else (no)
  endif
else (no)
  :Display empty state with import prompt;
endif

stop
@enduml
----

=== Acceptance Criteria

[source,gherkin]
----
Feature: View my questionnaires

  Scenario: View list with questionnaires
    Given the nurse has created 3 questionnaires in various statuses
    When the nurse opens the questionnaire list
    Then the system displays all 3 questionnaires
    And each entry shows title, status, and last-modified date

  Scenario: View list with no questionnaires
    Given the nurse has not created any questionnaires
    When the nurse opens the questionnaire list
    Then the system displays an empty state
    And prompts the nurse to import a questionnaire

  Scenario: Filter by status
    Given the nurse has questionnaires in Draft and Review status
    When the nurse filters by Draft
    Then only Draft questionnaires are displayed
----
